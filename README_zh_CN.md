# Netglimmer 发布（siyuan-plugin-netglimmer-Publish，原名 WebDAV 发布/一键发布）

一键把文档以「HTML (SiYuan)」格式发布到 WebDAV / FTP / SFTP 服务器（IIS WebDAV、IIS FTP、Nginx dav、vsftpd、OpenSSH-SFTP、群晖/威联通、Alist 等），发布后的页面与官方「文档分享」渲染效果一致：双链、块引用、块嵌入、图片资产全部保留。

## 它解决什么问题

手动「导出 HTML → 复制到网站目录」的两个痛点：

1. 每次改完都要重新导出、挑文件、复制；
2. 目录命名混乱，重复发布留下旧文件。

本插件把整条链路自动化：右键 → 按「HTML (SiYuan)」导出到思源临时目录 → 多路并发 PUT 上传到服务器 → 读回校验 → 清理临时文件。重复发布同一文档时默认走增量：思源运行时（每次导出都附带的那约 570 个逐字节相同的文件）已在服务器上就跳过重传，只传本文自有内容和有变化的文件，传完再清掉本目录里不再需要的旧资产。

> 注：思源 3.8.6 起，内核的导出接口不再写入 index.html（改由前端拼装后经单独的落盘接口写出）。v0.6.0 起插件内置了与前端逐字一致的拼装代码，发布时自行生成并上传 index.html，内容与手动导出的 HTML (SiYuan) 逐字节一致。

> v0.9.10：**把发布从「能用」推到「快且抗造」**，并补齐几个体验缺口。
>
> ①**并发上传**——原来 549 个文件是一个一个串行 PUT 的，慢在往返而不是带宽。现改为按协议取并发上限的上传池：WebDAV 6 路、SFTP 4 路、本地 4 路；FTP 保持 1 路（它只有一条控制连接，STOR 的 150/226 应答必须严格串行，并发会直接把会话打死）。本机实测首次全量发布 549 个文件 / 34.6 MB：WebDAV(IIS) 21 秒、SFTP 5 秒、FTP 4 秒、本地目录 2 秒。SFTP 另外做了写盘流水线——单个文件的 WRITE 请求由「一发一收」改为按 8 个一包滑动窗口（每包 24 KiB），运行时里那几个几 MB 的字体/JS 不再被往返拖死。
>
> ②**瞬时失败自动重试**——上传不再一抖就整次失败。错误按结构化字段分类（HTTP 状态码、FTP 应答码、SFTP 状态码、Node errno），只重试真正的瞬时故障：408/425/429/5xx、`ECONNRESET`/`ETIMEDOUT`/`socket hang up` 之类，指数退避 + 抖动最多 3 次；401/403/550 这类「配错了/没权限」的错误立刻失败并原样报出原因，绝不重复撞墙。连接类故障（SSH/FTP 会话断开）在重试前先单飞重建会话，避免多个 worker 同时重连。
>
> ③**少遍历一遍远端树**——增量发布本来就要 PROPFIND/LIST 一次远端目录，这次结果之前用完就丢，校验和清理孤立文件时又各遍历一遍。现在预检结果被复用：孤立文件直接拿它做基线；校验按代价选策略——本次上传的文件数不超过要遍历的目录数时，改为对上传过的文件逐个 SIZE/读回点验，否则仍走一次全树遍历兜底。
>
> ④**「有改动未发布」角标状态**——发布时记录的文档指纹此前只在看板里手动「检测」，现在由改动状态模块自动批量比对（一条 SQL 拿回所有已发布文档的 `max(updated)+count`，8 秒节流 + 每分钟兜底刷新），发布后又编辑过的文档，树角标从 🌐 变成警示色 ⬆，右键菜单同步变为「有改动，重新发布」。状态没变时不重绘 DOM，避免和 MutationObserver 互相触发。
>
> ⑤**进度与结果摘要**——进度条改为按字节推进（并按 150 ms 节流刷新），文案带上「第 N 个 / 共 M 个 · 当前文件名」；发布结束的消息直接说明本次真正上传了多少文件/多少字节、复用了多少个服务器已有文件、耗时几秒，不再需要打开看板猜「571 个文件 37.7 MB」到底传了多少。
>
> ⑥**失败可重试 + 看板改动自动标出**——看板里失败记录的按钮变为「重试」，且重试会回到该条记录当初用的那个协议（不是当前默认协议）；打开看板时改动状态由一次批量查询自动填好，不用再逐行点「检测」；看板顶部新增一行本次/最近发布的摘要（上传数、字节数、复用数、耗时）。
>
> 另外修掉一个一直没被注意的显示问题：设置面板与看板用了十余个思源主题里并不存在的 CSS 变量（`--theme-primary`、`--danger-color` 等），在明暗主题下都会退化成无色/透明，已全部映射到真实的 `--b3-theme-*`；「改动未发布」用的警示色取 `--b3-card-warning-color`（主题缺失时回落 `--b3-theme-error`）。四种协议（WebDAV / FTP / SFTP / 本地）均已带故障注入回归：注入 6 次瞬时错误后发布仍完整成功，注入 403 立即失败且不重试、历史记录保留「曾发布成功」标记。

> v0.9.11：**只做可维护性，不改行为**。源码拆成 `src/core.js`（日常要改的逻辑）+ `src/vendored/`（三段固定/移植数据：逐字移植的思源前端 `index.html` 拼装代码、侧边大纲 payload、GBK 码表），由零依赖的 `build.js` 拼回单个 `index.js`——发布产物与运行时行为跟 v0.9.10 **逐字节一致**（`node build.js --verify` 就是用来证明这一点的，拆分前后 index.js 哈希相同）。直接收益是干掉主文件里那几条约 7 万字符的超长行：`src/core.js` 3741 行中最长行只剩 372 字符，没有任何一行超过 500 字符，grep / diff / 审阅不再被移植代码污染；移植段自己也写明了维护约定（别顺手改格式；同步官方实现后必须重新过全量字节校验）。同时把凭据的事说清楚并在 UI 里提示：服务器密码是明文存在本机插件配置里的（思源没有系统钥匙串级别的存储接口，用本机可派生密钥做“加密”只是自欺，因此不做假加密），设置面板密码项下新增一行风险说明，README 补完整的缓解建议（不要把工作空间或 `settings.json` 原样同步/分享、分享配置前先删掉 `password` 字段、发布账号只授予目标目录写权限、工作空间放在磁盘加密的账户目录下）。详见「凭据存储说明」与「源码结构与打包」两节。

> v0.9.12：**把「会删错东西」的几件事补死**，并顺手清理了几个体验与安全缺口。
>
> ①**同名文档不再互相覆盖**——远端目录名只由标题决定，所以两篇「同名文档」以前会落进同一个目录：后发布的那篇会把前一篇的产物当孤立文件清掉。现在每个发布目录里留一个归属标记文件 `netglimmer-owner-<文档ID尾段>.json`（文件名即身份，四种协议都能靠一次浅列举读到），发现目录里是别人的标记时自动改用 `标题-<文档ID尾段>` 目录并提示，两边内容互不打扰。标记名故意**不带前导点**：vsftpd 默认 `hide_dotfiles=yes`，点开头的文件在 FTP 的 LIST/MLSD 里根本列不出来，冲突检测会静默失效。**注意：这个标记文件是刻意留在发布目录里的（会在目录列表里可见，内容只有本文档 ID），删掉它只会让同名冲突检测失效，不影响访问。**
>
> ②**远端路径加固**——「远端子目录」与文档目录名统一走 `safeSeg`：拒绝 `.` / `..` 段（否则本地协议的整树删除能删到基础目录外面），并按 UTF-8 字节截到 120 字节以内、保留码点边界、末尾补 `-`（中文标题 100 字符≈300 字节，ext4 单段上限 255 字节时 mkdir 会失败且原因完全看不出来）。
>
> ③**改名/迁移残留自动清理**——历史记录里存了本次实际使用的远端分段（`rootSegs`/`dirName`），重新发布时若发现本文档旧记录指向的目录已不是当前目录，会在上传成功后删掉那个旧目录；旧目录里若检测到别人的归属标记则跳过并写日志，绝不替别人做决定。
>
> ④**看板新增「试算」「取消发布」「复制地址」**——试算＝只统计会传多少文件/字节、能复用多少，远端零写入，用来在首次全量发布前确认体积；取消发布＝删除远端上这篇文档的发布目录（本地文档与历史保留，记录标为「已取消发布」，树角标随之消失），目录属于别人时拒绝执行，缺少定位信息的旧记录只提示不乱删；复制地址对 `http(s)://`、`ftp://`、`sftp://`、`file://` 一律可用（剪贴板 API 不可用时自动回退 execCommand）。本地目录记录的 `file://` 地址也重新给了「打开」按钮。
>
> ⑤**并发发布排队**——同一时间只跑一个发布任务，后点的进 FIFO 队列并提示「已排队」，不再出现两个任务互相删对方的文件。
>
> ⑥**半发布可辨识**——失败记录若已经建过远端目录或传了一部分文件，会明确提示「远端目录可能不完整」，并给出「先试算再重发」或「取消发布清空」的处置路径，不再留下说不清状态的目录。
>
> ⑦**设置补齐**——新增「单文件重试次数（1–6，默认 3）」「并发上传数（默认 0=按协议自动）」「单文件大小上限 MB（默认 64，0=不限制）」「输出调试日志」开关与「已知主机密钥 (SFTP)」一栏（显示已记录数量 + 清除全部按钮，此前 README 说要在设置里清空却根本没有这个入口）。SFTP 换服务器后可以直接清指纹重连。
>
> ⑧**其它**——文档树角标的 MutationObserver 改为优先观察真实树容器（容器不存在时才回退到 body），减少整页 DOM 抖动；插件卸载时关闭未完成的上传会话、隐藏进度面板、停掉改动定时器；界面文案语言匹配做了归一化（`zh-CN`、`zh_CN_` 之类都能落到正确字典，缺失键回退英文）；清掉了 8 条从未被引用的死文案键；打包元数据修正——`backends` 改为空（本插件是纯前端，没有内核侧代码）、`frontends` 用真实存在的 `desktop` / `desktop-window`（原先的 `desktop-store`、`desktop-linux` 不是合法取值）、补出 `readme.default` 指向的英文 `README.md`（此前该文件不存在，包里没有）。
>
> ⑨**新回归顺手抓出的三个真 bug**（都不是「理论上可能」，是测出来才发现的）：
>
> - 上面那四个新旋钮只进了 `readForm()`、没进 `applyFormToSettings()`，于是界面上改了、点「保存」就丢——设置项形同虚设。已补进写回路径，并由 `run-settings.js` 断言「表单值 → settings → 数值夹范围」。
> - `deleteTree()` 在 SFTP 与 WebDAV 上都只删子项、不删顶层目录（FTP 与本地当初是对的），所以「取消发布」和「改名残留清理」会在服务器上留下一个空目录。两种协议都补了顶层删除，`run-owner.js` 现在在本地 / FTP / SFTP 三条链路上都断言旧目录是**真的消失**而不只是被清空。
> - 归属标记是发布过程中第一个上传的文件，一旦它的 PUT 连续失败，整次发布会被判失败——可那时 549 个产物其实已经传完并校验通过了。现在标记写入降级为「尽力而为」：失败只告警（提示同名保护本次弱化），不再绑架发布结果。`run-inject.js` 专门加了这条断言。


## 安装

解压到 `{工作空间}/data/plugins/siyuan-plugin-netglimmer-Publish/`，重启思源。仅支持桌面端。

> 插件标识已由 `siyuan-plugin-webdav-publish` 统一更名为 `siyuan-plugin-netglimmer-Publish`（显示名 Netglimmer 发布 / Netglimmer Publish）。首次启动时插件会自动从旧标识目录迁移已保存的设置与发布历史，旧目录可放心删除。

## 配置

入口：思源「设置 → 插件市场/已加载插件 → Netglimmer 发布」的原生插件设置面板（未配置就点发布时会自动打开该面板）。

| 项 | 说明 |
|---|---|
| 传输协议 | WebDAV（默认）/ FTP / SFTP / 本地目录，四选一。四种协议各存一套地址与凭据，切换时互不覆盖；发布只使用当前选中的那一种 |
| 服务器地址 | WebDAV 填根 URL，如 `https://example.com/dav`；FTP/SFTP 填 `主机[:端口]`，如 `ftp.example.com` 或 `192.168.1.10:2121`（FTP 默认 21，SFTP 默认 22）；本地目录填绝对路径，如 `/var/www/html` 或 `D:\www\publish` |
| 用户名 / 密码 | 对应协议的账号；SFTP 仅支持密码认证；本地目录留空 |
| 远端子目录 | 可选，如 `publish`，所有文章放在这个目录下。不能含 `.` / `..` 段（会直接拒绝并说明原因，防止整树删除越界）；过长的中文标题会按 UTF-8 字节截到 120 字节以内并补 `-`，避免文件系统单段上限导致的 mkdir 失败 |
| 发布前清空远端旧目录 | 默认开。开启增量时不会整树删除（那会连运行时一起删、增量失去意义），只删本次目录内的孤立文件与改名残留目录 |
| 发布页面注入侧边大纲 | 默认开，等效手动跑 `add_toc.py` |
| 一键发布时包含子文档 | 默认开，决定右键那一个按钮是「单篇」还是「含子文档合并」 |
| 增量发布（跳过重复运行时） | 默认开，见 v0.9.7 |
| 单文件重试次数 | 1–6，默认 3；只重试瞬时故障（连接中断/超时/408/429/5xx），401/403/550 立刻失败不撞墙 |
| 并发上传数 | 0 = 按协议自动（WebDAV 6、SFTP/本地 4、FTP 1）；可手动 1–16，服务器弱或带宽小调低更快 |
| 单文件大小上限 (MB) | 默认 64，0 = 不限制；超限文件跳过并明确报错，避免整文件读进内存卡顿 |
| 输出调试日志 | 默认关。打开后在浏览器控制台输出每次请求/上传细节，排查发布失败用 |
| 已知主机密钥 (SFTP) | 显示已记录的指纹数量，「清除全部」用于换服务器/重装系统后重新接受指纹（TOFU 策略不会因为 README 说了却找不到入口而卡住） |

> **凭据存储说明（请知悉）**：服务器地址、用户名、密码以**明文**保存在插件配置里（思源工作空间 `data/storage/petal/siyuan-plugin-netglimmer-Publish/settings.json`，本机可读）。这是思源插件的通行做法——思源本身没有提供系统钥匙串级别的凭据存储接口，任何“加密”只要密钥还在本机，能读到你本机文件的程序同样能解密，所以这里不做假加密。实际风险与建议：①**不要**把整个工作空间目录（或 `data/storage/petal/` ）原样上传/同步到公开位置、网盘或聊天记录里；②把思源工作空间放在自己的账户目录下并开启磁盘加密（BitLocker/FileVault/LUKS）；③给发布用的服务器账号只授予目标子目录的写权限，不要用管理员账号；④换机器或分享配置时，手工把 `settings.json` 里的 `password` 字段删掉再分享。发布历史（`history.json`）不含密码，但会包含访问地址与文档名，同样按敏感处理。

导出参数与手动「导出 → HTML (SiYuan)」完全一致（是否添加标题等跟随思源「设置 → 导出」的全局配置），插件不再单独覆盖。

填完地址和账号后可点「测试连接」：WebDAV 先 PROPFIND 探测可达性与认证再做写探针（MKCOL → PUT → DELETE）；FTP/SFTP 先登录，再自动做一次写探针（建目录 → 上传已知大小临时文件 → 核对尺寸 → 删除）。全部通过才建议保存发布。SFTP 首次连接会在提示中给出主机密钥指纹并记录（TOFU），之后指纹变化会拒绝连接，需在设置的「已知主机密钥 (SFTP)」一栏点「清除全部」后重连。

> FTP/SFTP 使用思源桌面端内置 Node 的直接 socket 连接，不经过内核转发代理，因此没有 WebDAV 通道 32 MiB 单文件限制；但需要桌面端能直连服务器端口（公司代理/防火墙环境请先测试连接）。

## 使用

文档树右键任意文档，只有 **Netglimmer 一键发布** 一个入口（编辑区标题图标菜单同名）。是否把子文档合并为一篇，由设置里的「一键发布时包含子文档」开关决定（默认开启），不再占一条菜单项。文档发布过之后若又有编辑，该入口文案会变成 **「有改动，重新发布」**，直接点就是重发。

发布过程中右下角只有一个进度面板（阶段文字 + 按字节计算的进度条 + 当前文件名，刷新已节流不会刷屏），网络抖断会自动退避重试；成功后消息提示直接给出结论，形如：

`已发布：http://你的域名/publish/文章标题/｜本次上传 1 个文件 / 20.9 KB，复用服务器上 548 个运行时文件，共 1 秒`

（FTP/SFTP 给出带端口的 `ftp://` / `sftp://` 远端路径，需按站点映射自行访问。）

**文档树角标**：发布成功且内容一致的文档，标题后跟一个 🌐 角标；发布后正文又改过的，换成 ⬆ 警示色角标（鼠标悬浮有说明）。点击角标直接打开已发布页面。

**发布看板**：插件设置面板「发布看板」页签，或状态栏「发布看板」打开。表格按时间倒序列出每条发布记录（时间、文档、协议、成功/失败、文件数与字节数、访问地址、错误信息；同一文档同一协议只保留一条，重复发布仅刷新），每行支持：

- **打开 / 复制** —— 「打开」用浏览器打开已发布页面（`http(s)://` 与本地目录的 `file://` 都可点）；「复制」把地址放进剪贴板，`ftp://` / `sftp://` 这类没有浏览器直达的协议就靠它（剪贴板 API 在个别 webview 里不可用时自动回退 `execCommand`）；
- **改动状态** —— 打开看板时自动批量比对源文档当前指纹与发布时指纹，标记「未改动 / 有改动 / 未知」，无需逐行点；
- **重新发布 / 重试失败项** —— 成功记录显示「重新发布」，失败记录显示「重试」，都会按该条记录当时使用的协议重发（而不是当前默认协议）；
- **试算** —— 只统计「会传哪些文件、共多少字节、能复用多少」，不建目录、不删除、不上传（远端零写入、不写历史记录），首次全量发布前用它确认体积最稳妥；
- **取消发布** —— 删除远端上这篇文档的发布目录，本地文档与历史记录保留，记录标为「已取消发布」、树角标同步消失。目录里有别人的归属标记时拒绝执行；老记录没存远端分段信息时只提示、不猜路径。

同一时间只跑一个发布任务：后点的会排队并提示「已排队」，上一个结束后自动开始，避免两个任务在远端互相删对方的文件。发布失败时如果远端目录已经建好或传了一部分，会额外提示「目录可能不完整」，并给出「先试算再重发」或「取消发布清空」两条明确出路。

看板保留最近 300 条记录，可一键清空。

## 服务器端注意

- **IIS**：启用 WebDAV 发布功能后，注意 `web.config` 里 `webDAV` 的 `fileExtensions` 不能拦截 `.html/.css/.js/图片` 后缀；默认请求筛选会拒绝 `PUT` 中带点的某些扩展名，需逐项放行。
- **Nginx（Linux 迁移后）**：`dav_ext_module` 开启 `dav_methods PUT DELETE MKCOL;`，并加 `create_resources put;`（或依赖插件的 MKCOL）；`dav_access` 设置文件权限 `0644/0755` 以便 nginx 可读。
- WebDAV 目录必须同时是网站静态资源目录（或反代映射），发布即可访问，无需重启任何服务。
- **FTP / SFTP**：插件把文件写到登录用户可写的路径（FTP 为登录后的当前目录，SFTP 为用户主目录）；若网站静态目录不在该路径下，请把远端子目录设为软链/挂载点可达的位置，或在服务器端把站点根指向该目录。SFTP 需服务器启用 `sftp` 子系统（OpenSSH 默认启用 `internal-sftp` 即可）。
- **FTP 中文文件名自动适配**：插件会探测服务器能力（FEAT/OPTS）。服务器声明 UTF8 时按 UTF-8 传路径；不支持 UTF8 的服务器（常见于中文版 Windows 上的 FileZilla Server / 老 IIS，按系统 ANSI 代码页 GBK 解释字节）会自动改用 GBK 编码路径，使磁盘上落成真中文名、浏览器可用正常 URL 访问（已针对此类服务器实测：中文文档目录发布后浏览器直接打开成功）。
- **FTP 删除权限**：「发布前清空远端旧目录」与服务器的写探针清理需要 FTP 账号有删除权限。若服务器拒绝删除（如 FileZilla Server 未勾选 Delete），插件会自动改用固定名覆盖式探针并继续正常工作，但改名/删除旧文档留下的文件需要在服务器端手动清理——建议给 FTP 账号开启删除权限。
- **发布目录里的簿记文件**：每个发布目录会有一个小文件 `netglimmer-owner-<文档ID尾段>.json`（内容只有本文档 ID 与协议），插件用它判断「这个目录是谁的」，从而避免两篇同名文档互相删对方的内容。它会在静态目录列表里可见；如服务器端规则屏蔽 `netglimmer-owner-*`，页面访问不受影响，但同名冲突检测会失效（列不到标记＝当作没有主人）。

## 源码结构与打包（改代码的人看）

思源插件的运行时约定是「前端一次性执行 `index.js`」，没有 import 机制，所以**发布产物必须是单个 `index.js`**。本仓库在这个约束下做了最小程度的拆分：日常要改的逻辑都在主文件里，逐字移植/固定数据单独放，打包时用一个零依赖脚本拼回去。

```
siyuan-plugin-netglimmer-Publish/
├── src/
│   ├── core.js                  ← 日常在这里改：i18n 字典、helpers、FTP/SSH 客户端、
│   │                              上传器、容错（重试/并发池）、设置面板、看板、publish 主流程
│   └── vendored/
│       ├── index-html.js        ← 逐字移植的思源 3.8.6 前端 index.html 拼装代码
│       ├── toc.js               ← 侧边大纲注入 payload + injectToc
│       └── gbk-table.js         ← GBK/Unicode 码表（base64 单行数据，约 67 KB）
├── build.js                     ← 拼装脚本（只用 node 自带 fs，无 npm 依赖）
├── index.js                     ← 产物：src/core.js + 三段 vendored 拼回的单文件
├── plugin.json
└── i18n/{zh_CN,en_US}.json      ← 由 src/core.js 内嵌字典生成（键序一致、两份键集必须相同）
```

日常流程：

```bash
node build.js          # 改完 src/ 之后生成 index.js
node build.js --verify # 只校验：磁盘上的 index.js 是否与 src/ 拼装结果逐字节一致（不写文件）
node build.js --check  # 只校验 src/ 内部一致性：标记与文件是否一一对应、有无孤立段
```

规则与坑：

- **不要直接编辑 `index.js`**——它是产物，下一次 `node build.js` 会被覆盖。改动一律进 `src/core.js`（或对应的 vendored 文件），再 build。
- `src/core.js` 里的 `/* @@VENDOR:名字@@ … */` 是拼装标记（注释形式，运行时是空语句）；`src/vendored/*.js` 里 `/* @@SEGMENT-BEGIN@@ */` 之后的内容会被原样拼回，**首尾不要增删空行**，否则 `--verify` 会失败。
- 为什么把这三段搬出去：`index-html.js` / `gbk-table.js` 里有多条上万字符级的超长行（GBK 表那一行 70267 字符）。留在主文件里会让每次 grep、diff、代码审阅都被污染——搬走后 `src/core.js` 3741 行里最长行只有 372 字符，一条超过 500 字符的行都没有。
- 同步官方前端代码时（思源升级后 `buildIndexHtml` 相关实现可能变化）：先在思源里手动「导出 → HTML (SiYuan)」拿一份基准，再改 `src/vendored/index-html.js`，改完必须让发布产物的全量字节校验（`publish` 第 6.5 步，或本地 `run.js` / `run-multi.js` 回归）通过——这个插件的立身之本是「与手动导出逐字节一致」，不是「差不多就行」。
- 打包发布：`node build.js && node build.js --verify`，然后把 `index.js`、`plugin.json`、`README.md`（英文，`readme.default` 指向它，缺了会在插件详情里显示为空白）、`README_zh_CN.md`、`i18n/` 压成 zip（不要把 `src/`、`build.js` 放进插件包，思源用不到）。`plugin.json` 的 `backends` 必须为空（本插件没有内核侧代码）、`frontends` 只能用思源真实存在的取值（`desktop` / `desktop-window` / `browser-desktop` / `browser-mobile` / `mobile` / `all`），`desktop-store`、`desktop-linux` 这类是无效值。
- i18n 两份 JSON 是从 `src/core.js` 内嵌字典生成的，手改其中一份会在下次生成时被覆盖；新增文案请同时补 `zh_CN` 与 `en_US` 两处，并保证键集一致（回归脚本会断言）。

## 已知限制

- 导出格式当前固定 HTML (SiYuan)（还原度最高）；PDF / Word / Markdown 包后续版本加。
- 加密笔记本不支持发布（内核会拒绝明文导出）。
- WebDAV 上传在浏览器通道失败时回退内核 `/api/network/forwardProxy`（JSON + base64），回退路径下单个文件建议不超过 32 MiB；FTP/SFTP 为直连 socket，无此限制。
- SFTP 仅支持密码认证（不支持私钥/passphrase）；主机密钥为 TOFU 策略，服务器换密钥后需手动清空已记录指纹。
- 并发上传按协议取上限（WebDAV 6 / SFTP 4 / 本地 4）；FTP 恒为 1 路串行——单控制连接下多路 STOR 的应答会互相咬住，属于协议限制而非实现偷懒。可在设置里手动覆盖并发数。
- 单文件默认上限 64 MB（设置可调，0＝不限制）：超限文件跳过并报错，因为整文件要读进内存做字节校验。WebDAV 走内核 forwardProxy 回退时还受 JSON+base64 通道约 32 MiB 的实际限制。
- 同名文档的归属判定依赖发布目录里那个 `netglimmer-owner-*.json` 标记文件：服务器上手动删掉它、或用规则屏蔽该文件名时，两篇同名文档会被当成「目录没有主人」而各写各的（此时后发布的那篇会覆盖前者）。
- 「取消发布」只删该条记录里记录的远端分段；v0.9.12 之前的老记录没有这个信息，插件不会靠猜路径去删（只提示）。想清掉老记录对应的目录，先用同一协议重新发布一次（会补上分段信息）或手动删除。
- 改动检测基于文档块索引（块数 + 最后更新时间），仅比较思源内源文档；发布后直接改远端文件不会被识别。
